## Corrected findings

The first version did not snapshot application source code, allowed a build destination inside `src` or exactly `public`, and accepted overlapping source/backup/evidence roots. Its rollback covered rename errors but not the wrapper's later integrity check. Its PWA verifier lost five original manifest fields, minimum icon/shortcut counts, the Builder shortcut, and the top-level Workbox requirement. Inventory traversal order could also disagree with globally sorted manifests.

Those findings are corrected and exercised independently. The plan now snapshots project inputs and the full public tree. Only `project/dist` is accepted inside the project. Source, backup, evidence and staging guards reject unsafe overlaps and symlink ancestors. Inodes for TypeScript's existing emitted files must be independent before compilation. Public staging uses exclusive writes and a fresh UUID output. Post-promotion validation runs inside the transaction; failures restore the previous destination or its previous absence and preserve the rejected new output. Byte inventories are compared in canonical path order. PWA verification retains the original requirements and adds full public-asset byte checks and icon discovery checks.

## Scoped operating conditions and limits

- The root has explicitly frozen the selected raster source bytes. Keep all such bytes immutable for the lifetime of their linked source, runtime, build and backup aliases. Future image revisions must create a new file and rename its pathname; do not overwrite or chmod a shared inode. Normal tsc/Vite/PWA does not call the optional image writers. Optional `generate_mgs1_static_assets.py`, `normalizeSideOpsBackdrop.py`, `importDedicatedInteriorAtlas.py`, `splitCodecPortraitSheet.py` and arbitrary image-output savers must remain outside this frozen flow or adopt new-file replacement.
- The v2 validator checks the exact PNG signature or WebP RIFF signature, declared container length, image chunk type/size and bounded padded chunks, as well as complete SHA/length, regular paths and device identity. This is structural signature validation rather than a full decoder for every pinned file. The actual tiny WebP used in independent tests also decoded successfully; see `REAL_WEBP_SOURCE_DECODE_REVIEW.json`.
- A reviewed plan is invalid if its source graph, inputs, public tree, configuration, pins, module hash or old destination changes. Stop concurrent source/output writers during planning and execution. Installed dependencies and imports outside the project are explicitly frozen prerequisites and are not included in the project input snapshot.
- The two renames are individually atomic and have a brief destination pathname gap. Caught validation or promotion errors restore the old state. A process kill or machine crash can require reviewed recovery from the immutable prepared journal; these tools do not claim a single atomic exchange or automatic crash recovery.
- Source/output stages, rejected outputs and old directories remain preserved. Only the raster payload is shared; independent files and generated bundles still require disk space. Review the final plan's linked/copied byte counts against current free space. This reviewer did not execute a production sync/build and did not claim that any arbitrary production graph fits the available disk.

No unresolved blocker was found for the scoped local operation with those conditions and the reviewed hashes. Full production QA and publication remain the root's next steps.
