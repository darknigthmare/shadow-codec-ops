# Contrat d’exécution root

Le bundler est préparé uniquement. Il ne doit pas être lancé avec `--execute` avant le message de gel final de root. `--inspect-producers` est une observation en lecture seule des six dossiers de génération : il peut écrire un inventaire dans ce dossier d’outils et ne revendique aucune QA finale. Une planification finale exige aussi le gel root.

Le fichier `INPUTS_TEMPLATE.json` est volontairement `pending`, non confirmé et non gelé. Root doit créer un nouveau fichier d’entrée selon le schéma `cqc.github.pass8-review-bundle-inputs/1`, contenant les SHA256 finaux, puis fixer `confirmedByRoot: true`, `sourceState: frozen`, `status: passed`. Les treize livraisons doivent porter `allSixNativeSheetsPhysicallyViewedByRoot: true`. Les compteurs doivent correspondre exactement à `counts` du modèle. La branche source doit avoir les 39 ensembles attendus au moment du gel. Le champ obligatoire `sourceFreeze` donne `path` et `sha256` d’un fichier `cqc.pass8.current-source-freeze/1`, confirmé par root et épinglant exactement les sept fichiers runtime finaux. Ces pins sont revérifiés à la planification, avant la première écriture et après la conservation.

Chaque rapport final donne `name`, `path`, `sha256`, `status: passed`, `actualStatusField` et `actualReportStatus`. Le statut observé doit correspondre au statut épinglé ; les échecs non nuls et les résultats négatifs ou en attente sont refusés. Les preuves initiales, les erreurs et les essais conservés peuvent être ajoutés dans `extraFiles`, avec `path`, `sha256` et facultativement `provenanceRelativePath`, sans être qualifiés de QA finale. Ajouter notamment les rapports indépendants de gameplay, les contrôles source/origines, la QA finale autonome, les contrôles natifs et les contrôles de stockage/synchronisation pertinents.

Une preuve qui peut partager un inode avec une source mutable, notamment les `original-report-inodes` des sept rapports de test historiques, porte `requiresIndependentArchive: true` dans `extraFiles`. Elle est alors copiée une seule fois dans l’archive indépendante avant les liens R/S. Ce drapeau peut aussi protéger les scripts de revue ou de QA qui ne doivent pas partager leur inode de travail avec les preuves. `externalRetainedFiles: [{path, bytes, sha256, reason}]` conserve les grands snapshots de catalogue/roster à leur chemin original, épinglés et revérifiés, au lieu de recopier leur contenu dans chaque revue.

`DRAFT_ROOT_FACTS_PASS8.json` rassemble uniquement les faits disponibles avant la QA Shadow. Il reste `pending`, `confirmedByRoot: false`, `sourceState: in_progress`. Les rapports passés ont des périmètres explicites ; les emplacements `pendingReports` ne constituent aucune validation. Les 1 406 cas de la synthèse combinent 1 304 cas existants acquis auparavant et 102 cas REV3 ; les contrôles indépendants 38/66 sont des preuves séparées. Les 13 indicateurs de vues originales par root sont établis par son instruction ; la revue Canvas confirme 78 feuilles et 936 cellules visibles avec 58 groupes uniquement destinés à la revue. Root doit ajouter les véritables preuves de sync, QA/build Shadow et revue intégrée, puis créer un nouveau fichier de faits final confirmé avant le GO.

Une `evidenceTrees` est facultative. Chaque entrée donne `path`, `manifestPath`, `manifestSha256` et facultativement `provenanceRelativePath`. Son manifeste doit fournir `files: [{path, bytes, sha256}]` en chemins absolus exacts. Il doit énumérer tous les fichiers autorisés de ce sous-dossier sauf le manifeste lui-même. Choisir des sous-dossiers de preuves finales fermés ; ne pas inclure les fixtures, caches, dépendances, snapshots répétés de grands catalogues ou le dossier `/workspace` entier. Les autres preuves restent conservées à leurs sources et peuvent être épinglées comme fichiers précis.

Planifier après le gel avec `python /workspace/cqc-pass8-proof-bundle-tools/bundle_pass8.py --facts /workspace/ROOT_FACTS_PASS8.json --out /workspace/cqc-pass8-proof-bundle-tools/FINAL_PLAN.json`. Ce mode n’écrit ni R ni S. Revoir le budget d’allocation, les collisions et les SHA proposés. Root a autorisé les liens physiques pour les pièces PASS8 fermées et immuables : sorties natives, références PNG/JPG/GIF/WEBP, livraisons, documents et scripts de génération clos, revues et rapports QA finaux fermés. PASS9 et les nouveaux runs emploient de nouveaux dossiers ; aucune écriture future n’est autorisée dans ces pièces PASS8. Les sources runtime et les rapports de test mutables restent exclus de cette règle. Ils sont copiés indépendamment une seule fois dans `R/preparation/reprise-pass8-provenance/final-source-archive`, puis seuls les liens depuis cette archive immuable vers les preuves R/S sont permis. Le catalogue final a ainsi une seule nouvelle copie physique indépendante. Les liens exigent le même système de fichiers, les SHA complets et une création exclusive. Le script exige une réserve de 80 Mio avant de commencer et refuse un budget insuffisant avant toute écriture de bundle.

Après revue root, exécuter avec `--execute --freeze-sha256 SHA256_DU_FICHIER_ROOT_FACTS`. La commande conserve dans `R/preparation/reprise-pass8-provenance` et `S/docs/cqc-reprise/pass8`, sans écrire les sources d’exécution, les assets publics, Git ou Vercel. Elle conserve un journal progressif dans ce dossier d’outils. Si une destination diffère, le comportement par défaut est de s’arrêter. `--preserve-existing` n’est à utiliser qu’après revue des collisions : chaque ancien contenu est conservé dans un fichier voisin `.previous-SHA256` avant le remplacement atomique. Les fichiers source et les contenus précédents ne sont jamais supprimés.

La commande doit être exécutée pendant une période stable des sources, des livraisons, des outils et des preuves. Elle revérifie les SHA de toutes les sources et destinations ainsi que l’état Git extérieur au dossier de revue. Son manifeste contient toutes les empreintes et les qualifications, sans recopier les octets du catalogue dans le manifeste. Les archives historiques, les films complets et les manuels complets sont exclus ; seules les deux préimages source `.json.before.gz` et `.js.before.gz` déjà conservées sous `action-mapping-revisions` bénéficient d’une exception gzip précise. Elle ne sync pas, ne commit pas et ne publie pas.
